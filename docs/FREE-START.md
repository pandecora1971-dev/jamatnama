# ফ্রি প্ল্যানে শুরু করার গাইড

এই গাইড অল্প ব্যবহারকারী নিয়ে পরীক্ষামূলকভাবে শুরু করার জন্য। সব ধাপের বিস্তারিত [DEPLOYMENT.md](DEPLOYMENT.md)-এ আছে; এখানে শুধু ফ্রি প্ল্যানের পার্থক্যগুলো লেখা হয়েছে।

**এই ফ্রি সেটআপ লাইভ অ্যাকাউন্টে পরীক্ষা করা হয়নি।** ফ্রি প্ল্যানের সীমা সময়ের সঙ্গে বদলাতে পারে। শুরুর আগে প্রতিটি সেবার বর্তমান সীমা দেখে নিন, আর [DEPLOYMENT.md](DEPLOYMENT.md)-এর ১০ নম্বর অংশের পরীক্ষাগুলো করুন।

## শুরুর আগে তিনটি সিদ্ধান্ত

১. **Vercel Hobby শুধু ব্যক্তিগত, অ-বাণিজ্যিক ব্যবহারের জন্য।** আপনার সাইট এই শর্তে পড়ে কি না, Vercel-এর শর্ত পড়ে নিজে নিশ্চিত করুন। দান, বিজ্ঞাপন বা কোনো প্রতিষ্ঠানের সঙ্গে যুক্ত থাকলে শুরু থেকেই Pro নিন।

২. **ফ্রি Supabase-এ ডাউনলোডযোগ্য ব্যাকআপ নেই।** ব্যাকআপ আপনাকে নিজে নিতে হবে। আসল রিপোর্ট আসা শুরু হলে সবার আগে Supabase Pro নিন।

৩. **ম্যালওয়্যার স্ক্যানারের জন্য একটি সবসময় চালু কম্পিউটার লাগবে।** এটি কোনো ফ্রি হোস্টিংয়ে চলে না। স্ক্যানার না চললে রিপোর্ট জমা হবে, কিন্তু পর্যালোচক প্রমাণের ফাইল খুলতে পারবেন না।

## ধাপ ১: Hobby-র cron সেটিং

প্রজেক্টের `vercel.json`-এ পরিষ্কারের কাজ প্রতি ১৫ মিনিটে চলে। Vercel-এর একটি পাতায় Hobby-তে দিনে একবারের সীমা আছে, তাই সেটিং অনুযায়ী ডিপ্লয় ব্যর্থ হতে পারে। ডিপ্লয়ের আগে দিনে একবারের সেটিং বসান:

```bash
cp vercel.hobby.json vercel.json
```

এটি প্রতিদিন রাত ২টায় (বাংলাদেশ সময়) চলবে। Hobby-তে নির্দিষ্ট সময়ের চেয়ে কিছুটা আগে-পরে চলতে পারে। ফলে অসম্পূর্ণ আপলোড ও মেয়াদোত্তীর্ণ তথ্য পরিষ্কার হতে এক দিন পর্যন্ত দেরি হতে পারে। এতে নিরাপত্তা কমে না, শুধু অপ্রয়োজনীয় ফাইল কিছুটা বেশি সময় জায়গা দখল করে রাখে।

## ধাপ ২: ফ্রি সীমার মধ্যে থাকার সেটিং

Vercel Environment Variables-এ এই মানগুলো যোগ করুন:

| সেটিং | মান | কারণ |
|---|---|---|
| `UPLOAD_BUDGET_TOTAL_GB` | `4` | R2-এর ফ্রি ১০ GB-এর মধ্যে মূল ফাইল ও ব্যাকআপ কপি রাখতে |
| `UPLOAD_BUDGET_DAILY_GB` | `1` | একদিনে জায়গা ভরে যাওয়া ঠেকাতে |
| `UPLOAD_MAX_VIDEO_MB` | `200` | একটি ভিডিওতেই জায়গা শেষ না হতে |
| `UPLOAD_MAX_AUDIO_MB` | `50` | |
| `UPLOAD_MAX_TOTAL_MB` | `300` | এক রিপোর্টের মোট আকার |
| `DB_POOL_MAX` | `3` | ফ্রি ডেটাবেসের সংযোগ বাঁচাতে |

ব্যাকআপ বাকেট না রাখলে `UPLOAD_BUDGET_TOTAL_GB` ৮ পর্যন্ত করতে পারেন। তবে তখন R2-র কোনো সমস্যায় প্রমাণের ফাইলের দ্বিতীয় কপি থাকবে না।

সীমা পূর্ণ হলে নতুন ফাইল নেওয়া বন্ধ হবে, কিন্তু ফাইল ছাড়া রিপোর্ট জমা চলবে। কোনো ডেটা মুছে যাবে না।

জমা দেওয়ার ফর্মে সার্ভারের আসল সীমা দেখায়। সাইটের প্রশ্নোত্তর ও নির্দেশনার লেখায় নির্দিষ্ট সংখ্যা নেই, তাই ফ্রি বা পেইড যেকোনো সেটিংয়ে লেখা সঠিক থাকে।

## ধাপ ৩: নিয়মিত ব্যাকআপ

প্রতিদিন নিজের কম্পিউটার থেকে চালান:

```bash
npm run db:backup -- /restricted/backups/backup-date
```

প্রমাণের ফাইলের কপি:

```bash
R2_BACKUP_BUCKET=jamatnama-evidence-backup npm run r2:backup
```

ব্যাকআপ এনক্রিপ্টেড হলেও সীমিত অ্যাক্সেসের জায়গায় রাখুন। `BACKUP_ENCRYPTION_KEY` ও `MFA_ENCRYPTION_KEY` ব্যাকআপ থেকে আলাদা জায়গায় রাখুন। এই key হারালে ব্যাকআপ পড়া যাবে না।

## ধাপ ৪: যা নজরে রাখবেন

- **Supabase pause:** এক সপ্তাহ খুব কম ব্যবহার হলে ফ্রি প্রজেক্ট থেমে যেতে পারে। ডেটা থাকে, কিন্তু ড্যাশবোর্ড থেকে আবার চালু না করা পর্যন্ত সাইট 503 দেখাবে। `/api/health`-এ একটি uptime monitor রাখুন।
- **ডেটাবেসের আকার:** ফ্রিতে ৫০০ MB। ফাইল এখানে থাকে না, তাই শুরুতে যথেষ্ট হওয়ার কথা।
- **R2:** ফ্রিতে মাসে ১০ GB জায়গা। এর বেশি হলে বিল হবে, সাইট বন্ধ হবে না।
- **Team panel:** স্টোরেজের ব্যবহার আর স্ক্যানের অপেক্ষায় থাকা ফাইলের সংখ্যা এখানে দেখা যায়।
- **Vercel Firewall:** ফ্রি প্ল্যানে কতটুকু rate limit পাওয়া যায় তা ড্যাশবোর্ডে দেখুন। না পেলে প্রতি-IP সুরক্ষা কম থাকবে; অ্যাপের নিজের সীমাগুলো তখনও কাজ করবে।

## ধাপ ৫: পেইডে যাওয়া

এই ক্রমে করুন:

১. `npm run db:backup` দিয়ে নতুন ব্যাকআপ নিন, আর `npm run r2:backup` চালান।
২. একই Supabase প্রজেক্টকে **Pro** করুন। নতুন প্রজেক্ট খুলবেন না। আপগ্রেডে ডেটা থাকার কথা, তবে ডকুমেন্টে এটি সরাসরি লেখা পাইনি, তাই আগের ধাপের ব্যাকআপ বাদ দেবেন না।
৩. `vercel.json` আগের অবস্থায় ফেরান, যাতে পরিষ্কারের কাজ প্রতি ১৫ মিনিটে চলে:

   ```json
   { "regions": ["bom1"], "crons": [{ "path": "/api/cron/maintenance", "schedule": "*/15 * * * *" }] }
   ```

৪. Vercel প্রজেক্টকে **Pro**-তে নিন।
৫. Environment Variables থেকে ধাপ ২-এর সীমাগুলো মুছে দিন বা বাড়িয়ে দিন, তারপর আবার ডিপ্লয় করুন।
৬. একটি পরীক্ষামূলক রিপোর্ট জমা দিন। পর্যালোচনা, প্রকাশ ও প্রত্যাহার পরীক্ষা করুন। পুরোনো ট্র্যাকিং কোড ও প্রকাশিত রিপোর্ট ঠিক আছে কি না দেখুন।

R2-তে কিছু বদলাতে হবে না; একই বাকেট চলতে থাকে। Vercel-এ আপনার রিপোর্ট বা প্রমাণ জমা থাকে না।

## ফ্রি প্ল্যানে যা পাবেন না

- স্বয়ংক্রিয় দৈনিক ডাটাবেস ব্যাকআপ
- সবসময় চালু থাকার নিশ্চয়তা (Supabase pause হতে পারে)
- বড় ভিডিও গ্রহণ করার মতো জায়গা
- বড় ট্রাফিক সামলানোর ক্ষমতা: ছোট ফ্রি ডেটাবেসে লোড টেস্ট করা হয়নি

তাই সংবেদনশীল আসল রিপোর্ট নিয়মিত আসা শুরু হলে ফ্রি প্ল্যানে বেশি দিন থাকবেন না।
